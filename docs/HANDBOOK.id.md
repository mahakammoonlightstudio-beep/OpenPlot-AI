## Memulai

OpenPlot AI adalah studio chat dan cerita yang lokal-first. Chat, proyek, story bible, dan pengaturanmu tersimpan dalam satu file SQLite di mesinmu — hanya permintaan ke model yang keluar dari aplikasi.

## 1. Tambah provider
Buka Settings → AI Providers lalu pakai **Smart setup** (pilih preset → tempel key → tes) atau tambah provider manual.

Setiap baris provider butuh:
- **Base URL** — akar API, misalnya `https://api.openai.com/v1`.
- **API key** — terenkripsi saat vault OS tersedia.
- **Model** — ambil dengan *Test & fetch*, atau tulis manual.

## 2. Pilih model
Pengaturan → Settings → Models menampilkan setiap model dengan chip kemampuannya. Pilih satu sebagai bawaan, atau biarkan **Auto (disarankan)**.

## 3. Mulai chat
`Ctrl+N` membuat chat. Ketik, `Enter` untuk kirim, `Shift+Enter` untuk baris baru. `Ctrl+K` membuka command palette dari mana saja.

## 4. Beri proyek (opsional)
Proyek menyimpan story bible, bab, dan blok konteks. Sambungkan proyek ke chat dan model melihat kanonmu alih-alih menebak.

> Lanjutkan dengan artikel chat, file, skill, dan story bible, dalam urutan itu.

## Dasar chat

## Mengirim
- `Enter` mengirim; `Shift+Enter` baris baru.
- Composer tumbuh sampai sekitar delapan baris, lalu menggulir.
- `Esc` menutup popover model atau skill.

## Berhenti dan mengulang
Saat balasan mengalir tombol kirim berubah menjadi **Stop**. Berhenti menyimpan teks yang sudah ada — itu pesan sungguhan, bukan buangan.

**Regenerate** menjalankan ulang giliran asisten terakhir. Balasan sebelumnya tetap ada di menu pesan agar kamu bisa membandingkan.

## Override per chat
Header menampilkan model, meter token, dan chip proyek. Setiap chat menyimpan:
- model dan override temperature,
- system prompt (menggantikan yang global hanya untuk chat ini),
- pengaturan thinking dan anggarannya,
- goal sesi — instruksi tersemat yang masuk ke setiap prompt,
- pengecualian skill per chat.

## Merapikan
- **Folder** mengelompokkan chat di sidebar.
- **Pin** menahan chat di atas.
- **Ganti nama** dari baris chat atau header.
- Menghapus chat menghapus pesan dan file terlampirnya. Tidak ada undo — ekspor dulu lewat Settings → Data bila chat itu penting.

## Apa yang benar-benar dilihat model
Buka Settings → agent.md dan tekan **Pratinjau prompt** untuk melihat system prompt persis untuk pesan berikutnya: sistem, agent.md, proyek, memori, skill, goal, gaya, tools, lampiran.

## File di chat

Ikon paperclip di composer melampirkan file ke **pesan berikutnya** saja. Lampiran tampil sebagai kartu di atas input — tidak ditempel ke kotak teks, jadi tidak ada yang terkirim dua kali.

## Batasan
| Batasan | Nilai |
| --- | --- |
| File per pesan | 8 |
| Per file | 256 KB |
| Total per pesan | 1 MB |

Batasan dicek sebelum pesan ditulis: file kebesaran atau biner ditolak dengan satu pesan yang jelas dan composer tetap utuh.

## Yang bisa dilampirkan
- File teks: `.md`, `.txt`, `.json`, `.csv`, kode sumber, `.srt`.
- Entri story dan bab dari proyek aktif.

File biner (gambar, PDF, `.docx`) tidak diurai; ekspor teksnya dulu.

## Sampai ke model
Isi lampiran ditambahkan ke system prompt di bagian *Attached files*, lengkap dengan nama, jenis, dan ukuran. File panjang dipotong dan model diberi tahu.

File disimpan bersama pesan, jadi membuka chat lagi tetap menampilkan kartunya. Menghapus pesan atau chat menghapus filenya.

## Model dan cache prompt

## Chip kemampuan
Setiap baris model menunjukkan kemampuannya dari tiga sumber:
1. **Preset dikenal** — fakta bawaan untuk model umum: konteks, output, reasoning, cache.
2. **Probe** — tombol *Verify* menanyakan langsung ke provider.
3. **Observasi** — angka usage dari balasan nyata.

Chip hanya petunjuk. Model yang mengaku tanpa reasoning tetap jalan; kontrol thinking menyembunyikan diri di mode `auto`.

## Penyetelan per model
Settings → Models → *Edit* membuka kartu model: context window, batas output, override temperature, dukungan reasoning, mode cache. Override disimpan per pasangan `provider::model`.

## Cache prompt
Sebagian provider memakai ulang awalan prompt yang tidak berubah dan menagihnya lebih murah. Footer chat menampilkan token ter-cache saat provider melaporkannya:

- `cache 0%` — tidak ada yang dipakai ulang.
- `cache 62%` — sebagian besar awalan prompt dari cache.

Cache bergantung pada awalan yang stabil. Mengedit pesan lama atau mengganti system prompt membatalkannya — itu wajar, bukan bug.

## Thinking dan reasoning

Model yang mendukung reasoning bisa memakai token sebelum menjawab. OpenPlot menampilkannya sebagai **Thinking**.

## Kontrol
Ikon otak di composer punya tiga keadaan: mati, nyala, dan *auto*. Dengan `thinkingUi = auto`, model yang tidak bisa reasoning tidak melihat kontrol ini sama sekali.

## Anggaran
Anggaran adalah batas token reasoning untuk chat ini, dibatasi context window model. Anggaran lebih besar tidak otomatis lebih baik: ia menambah latensi dan biaya, dan sebagian besar tugas selesai jauh sebelum batas.

## Ke mana outputnya
Reasoning mengalir ke blok yang bisa dilipat di atas balasan. `thinkingDisplay` menentukan:
- **auto** — terbuka saat mengalir, terlipat saat jawaban mulai.
- **expanded** / **collapsed** — dikunci.

Teks reasoning disimpan bersama pesan dan tidak pernah dimasukkan kembali ke prompt berikutnya.

## Setelan praktis
| Tugas | Anggaran |
| --- | --- |
| Edit cepat, chat | mati |
| Perencanaan, kritik | 1–2k |
| Masalah kontinuitas atau plot | 4k+ |

## Skill

Skill adalah blok instruksi bernama yang disuntikkan ke system prompt: aturan kontinuitas, protokol kritik, panduan genre. Skill bersifat global; setiap chat bisa membisukannya.

## Bawaan
Enam skill ikut terpasang: continuity, prose, dialogue, pacing, beta reader, dan architect. Semuanya bertanda **Builtin**:
- teksnya bisa kamu ubah,
- **Reset** mengembalikan versi bawaan,
- tidak bisa dihapus.

## Menambah skill
Settings → Skills → **Tambah skill** membuka editor dengan nama, deskripsi, isi, dan pratinjau blok yang disuntikkan. **Simpan** membuatnya **nonaktif** — tidak ada yang sampai ke model sampai kamu menekan **Aktifkan**, jadi skill setengah jadi tidak pernah menyentuh balasan.

Mulai dari templat (Kosong, Line editor, Beta reader, Worldbuilding) atau impor file `.md`. Ekspor menghasilkan file markdown portabel.

## Kontrol per chat
Composer menampilkan chip `Skill n` saat ada skill aktif. Popover-nya mendaftar semua skill aktif dengan switch; mematikan satu menyimpan id-nya di daftar pengecualian chat tersebut.

## Ukuran prompt
Blok skill dibatasi 12.000 karakter. Skill yang tidak muat diganti `[skill truncated: …]` alih-alih dipotong di tengah instruksi.

## Kapan skill merugikan
Tiga skill yang bertumpang tindih sering saling bertentangan. Aktifkan dua atau tiga per proyek dan biarkan agent.md membawa aturan umum.

## agent.md

agent.md adalah file instruksi permanenmu. Ia masuk ke setiap chat dengan label *Agent instructions (highest priority after the system prompt)*.

## Isi yang cocok
- Aturan suara dan craft yang berlaku untuk semua tulisanmu.
- Etiket tools: baca sebelum menulis, tanya sebelum edit destruktif.
- Hal yang tidak boleh dilakukan model.

Yang **tidak** cocok: fakta cerita (story bible), alur kerja yang bisa dipakai ulang (skill), instruksi sekali pakai (pesan itu sendiri).

## Prioritas
1. System prompt dan aturan keamanan provider.
2. agent.md.
3. Konteks proyek.
4. Skill.
5. Gaya balasan.
6. Memori.
7. Pesanmu.

Saat dua aturan bertabrakan, yang lebih tinggi menang; model diminta menyebutnya dalam satu baris alih-alih memilih diam-diam.

## Mengedit
Settings → agent.md: edit, lalu **Pratinjau prompt** untuk melihat hasil gabungan. **Pulihkan bawaan** memuat teks bawaan, templat memberi titik awal novelis, editor, atau minimal, dan penghitung menunjukkan karakter serta perkiraan token.

Draf bertahan saat berpindah bagian; **Buang** menghapusnya.

## Upgrade
Saat versi baru membawa bawaan yang lebih baik, agent.md diganti **hanya jika masih persis sama dengan teks bawaan lama**. Ubah satu karakter saja, tidak ada yang disentuh — toast sekali memberi tahu bahwa bawaannya berubah.

## Story bible

Story bible bersifat per proyek: karakter, lokasi, item, faksi, lore, timeline, dan outline.

## Entri
Setiap entri punya **jenis**, **judul**, **isi** (markdown), **tag**, dan **tautan** opsional ke entri lain. Satu fakta per entri membuat pencarian bekerja — satu entri "segala hal tentang perang" sulit dicari dan cepat basi.

## Tools yang dipakai model
Saat tools aktif, model bisa `search_story`, `read_story_bible`, `create_story_entry`, dan `update_story_entry`. Penulisan mengembalikan ringkasan perubahan dan tampilan menyegarkan diri.

## Sambungkan ke chat
Chat yang terikat proyek mendapat deskripsi proyek sebagai konteks. Tarik entri tertentu ke composer alih-alih membuang seluruh bible.

## Kebiasaan kanon yang baik
- Satu subjek per entri, dinamai seperti kamu akan mencarinya.
- Perbarui entri saat cerita berubah; kanon basi lebih buruk daripada tidak ada.
- Pakai tautan untuk relasi alih-alih mengulang teks.

## Bab

Bab menyimpan naskah sesungguhnya. Setiap bab punya judul, isi, status (`draft`, `revising`, `done`), posisi, dan jumlah kata.

## Menulis di aplikasi
Editor menyimpan saat kamu menekan **Simpan** — tidak ada penulisan diam-diam di tengah kalimat. Riwayat versi menyimpan snapshot tiap simpan sehingga kamu bisa membandingkan atau kembali.

## Dengan model
Minta satu adegan dan model bisa `create_chapter`, `update_chapter`, `append_to_chapter`, dan `read_chapter`. Menambahkan lebih aman daripada menulis ulang: tulisanmu tidak tersentuh.

Agen menulis ke bab, bukan ke chat, saat keluarannya panjang. Prosa tetap di luar transkrip dan riwayat prompt.

## Status dan alur
Status bab mengisi Story Flow, yang mengubah beat jadi bab. Jumlah kata mengisi Writing Stats.

---

## Alur cerita

Flow adalah papan outline: **act → beat → bab**.

## Beat
Beat adalah judul, ringkasan, dan status (`planned`, `written`, `cut`). Pindahkan beat antar act, urutkan ulang, dan hubungkan ke bab saat menjadi prosa.

## Bekerja dengan model
Agen cerita bisa mengusulkan beat sheet, menjabarkan satu beat jadi rencana adegan, atau memeriksa bahwa setiap act punya tikungan. Usulan tinggal di `story_plans` sampai kamu setujui, jadi saran buruk tidak pernah mengedit outline-mu.

## Alur praktis
1. Beat hanya untuk act berjalan — act masa depan tetap kabur.
2. Jabarkan beat berikutnya jadi bab saat kamu mulai menulis.
3. Tandai beat selesai saat babnya ada.

## Statistik menulis

Statistik menghitung kata yang benar-benar kamu tulis, per hari dan per proyek. Semuanya lokal dan tidak pernah diunggah.

## Yang dihitung
- Edit isi bab, balasan chat yang kamu simpan, dan entri story.
- Kata yang dihapus dihitung negatif, jadi salin-tempel dan penghapusan tidak menggelembungkan grafik.
- Hanya selisih yang dicatat — menulis ulang kalimat yang sama lima kali tidak menambah kata.

## Membaca grafik
- **Hari ini** berganti tengah malam lokal.
- **Streak** menghitung hari berurutan dengan selisih positif.
- **Per proyek** menunjukkan ke mana tulisannya pergi.

Angkanya perkiraan: ini grafik motivasi, bukan jejak audit.

## Ekspor

## Chat
- **Markdown** — seluruh percakapan dengan peran dan waktu.
- **JSON** — pesan plus metadata, untuk diolah di tempat lain.
- Keduanya tersedia dari palette (`Ctrl+K`) dan header chat.

## Bab dan proyek
Proyek diekspor sebagai satu file Markdown atau EPUB, bab berurutan, dengan story bible sebagai lampiran bila diminta.

## Backup penuh
Settings → Data mengekspor semuanya sebagai JSON: chat, proyek, story bible, bab, prompt, gaya, skill, pengaturan. API key tidak disertakan.

Restore bersifat merge, bukan replace: baris dengan id sama diperbarui, baris baru ditambahkan, tidak ada yang dihapus.

> Ekspor sebelum upgrade versi. Biayanya satu klik dan itu satu-satunya backup yang tidak dibuat aplikasi untukmu.

## Pengaturan

Pengaturan dikelompokkan berdasarkan tujuanmu, bukan model data:

- **AI** — provider, model, perilaku.
- **Chat** — gaya, skill, agent.md.
- **Tampilan** — tema, aksen, ukuran font.
- **Data** — memori, penggunaan, backup dan reset.
- **Ekstensi** — plugin, automasi, MCP *(mode lanjutan)*.
- **Tentang** — versi, lokasi data, vault kredensial, panduan.

## Pencarian
Kotak pencarian di atas nav menemukan kontrol, bukan hanya bagian: ketik `cache` untuk mendarat di baris cache pada halaman model. `↑`/`↓` berpindah, `Enter` melompat dan memfokuskan kontrol, `Esc` membersihkan.

## Sederhana vs lanjutan
Mode sederhana menyembunyikan parameter model lanjutan dan grup Ekstensi. Tidak ada yang dihapus — *Tampilkan pengaturan lanjutan*, juga di palette, mengembalikan semuanya, dan pilihannya diingat.

## Reset
Setiap bagian bisa mereset bawaannya sendiri. *Reset semua data* di Settings → Data menghapus segalanya dan tidak bisa dibatalkan; ekspor dulu.

## Plugin

Plugin adalah file JavaScript lokal dengan hook. Plugin berjalan di proses utama dengan akses yang sama seperti aplikasi: pasang hanya kode yang kamu tulis atau baca.

## Bentuk
```js
module.exports = {
  name: 'word-count-logger',
  hooks: {
    'message:new': (payload, api) => api.log('message ' + payload.role)
  }
}
```

## Hook
Yang dijalankan aplikasi saat ini: `chat:new` (baris chat dibuat) dan `message:new` (pesan disimpan).

`app:ready`, `chat:send`, `chapter:saved`, `project:created`, dan `skill:enabled` ada di API plugin tetapi belum disambungkan — anggap rencana, dan jalankan nama hook-mu sendiri bila perlu sekarang.

## Perilaku
- Plugin nonaktif tidak pernah dimuat, bukan dimuat lalu diblokir.
- Error ditangkap per hook dan ditulis ke log plugin; plugin rusak tidak merusak chat.
- Plugin mendaftarkan perintah dengan `context.registerCommand`; daftar baris di Pengaturan → Plugin menampilkan log-nya.

Lihat `docs/PLUGIN_API.md` di repositori untuk permukaan lengkapnya.

## Server MCP

MCP (Model Context Protocol) adalah cara model memanggil tools di luar aplikasi: helper filesystem, indeks pencarian, database.

## Status di versi ini

Settings → MCP menyimpan definisi server secara lokal — nama, perintah, argumen, variabel lingkungan, dan tanda aktif. **Bridge yang menjalankan prosesnya, mendaftar tool-nya, dan mengeksposnya ke model belum ada di versi ini.** Definisi yang tersimpan tidak pernah menjalankan apa pun; mengaktifkannya adalah persiapan untuk rilis yang membawa bridge-nya.

Rencananya dan detail protokolnya ada di `docs/PLUGIN_API.md` dan rencana rilis di `docs/superpowers/plans/`.

## Yang bisa dilakukan sekarang

- Siapkan registry: tambahkan server yang kamu inginkan, dengan perintah dan argumen yang persis, agar nanti cukup satu saklar.
- Baca perintahnya sebelum menyimpan. Server MCP berjalan sebagai proses lokal dengan izinmu; perlakukan definisinya seperti skrip yang akan kamu jalankan.

## Yang akan dilakukan bridge-nya

- Menjalankan hanya server yang aktif, setelah jendela siap, dan mematikannya saat keluar.
- Berbicara JSON-RPC 2.0 newline-delimited lewat stdio: `initialize`, `tools/list`, `tools/call`.
- Menampilkan tool-nya sebagai `mcp__{server}__{tool}` saat tools aktif, dengan timeout panggilan dan batas ukuran hasil.
- Menampilkan titik status per server (starting, connected, error), jumlah tool, error terakhir, dan log yang bisa difilter.

Sementara itu, tools cerita milik aplikasi adalah yang benar-benar bisa dipanggil model — lihat artikel skill dan story bible.

## Privasi dan data

## Lokal secara bawaan
Semua tersimpan di file SQLite pada folder data pengguna, terlihat di Settings → Data: chat, pesan, lampiran, proyek, story bible, bab, prompt, skill, pengaturan.

Tanpa analitik, tanpa telemetri, tanpa akun.

## Yang keluar dari mesin
Hanya permintaan yang kamu kirim: system prompt (bisa memuat agent.md, konteks proyek, skill, dan file terlampir), riwayat percakapan, dan pesanmu. Semuanya langsung ke provider yang kamu atur — tidak ada proxy di antaranya.

Gambar dan file dikirim sebagai teks. File biner ditolak, bukan diunggah.

## API key
Key terenkripsi saat vault kredensial OS tersedia; jika tidak, aplikasi mengatakannya di Settings → Data. Key tidak pernah masuk ke ekspor, log, atau pesan error.

## Menghapus
*Reset semua data* menghapus setiap baris dan isi file. Backup saat migrasi skema (`.bak`) tetap ada di sebelah database — hapus manual bila ingin bersih total.

## Pemecahan masalah

## "No model selected"
Chat belum punya model dan Auto tidak bisa menentukan. Pilih bawaan di Settings → Models, atau pilih model di composer.

## 401 / 403 dari provider
Key salah, kedaluwarsa, atau tidak punya akses ke model itu. Tempel ulang, lalu **Verify** modelnya.

## 404 atau "model not found"
Nama model tidak ada untuk provider itu, atau base URL kehilangan `/v1`. Pakai *Test & fetch* untuk melihat daftar sebenarnya.

## Balasan kosong saat tools aktif
Sebagian model mengirim tool call tanpa teks. Aplikasi mencoba sekali lagi; bila berulang, matikan tools untuk chat itu atau ganti ke model yang andal memakai tools.

## Rate limit
Tunggu, atau ganti provider. Teks error dari provider ditampilkan apa adanya agar kamu bisa melihat waktu reset.

## Aplikasi terasa lambat
Chat panjang memuat 80 pesan terbaru lebih dulu. Bila mengetik terasa berat, tutup popover model dan pastikan chat tidak membawa puluhan lampiran.

## Masalah database
Migrasi yang gagal membiarkan file utuh dan melaporkan errornya. Kembalikan salinan `.bak` di sebelah database, atau ekspor dari mesin lain.

Masih macet? Issue tracker repositori adalah jalur tercepat: sertakan versi dari Settings → About dan teks error persisnya.
