# OpenPlot AI v1.2.3 — “Studio UX” Implementation Plan

> **For agentic workers:** implement task-by-task, in order, and tick the `- [ ]` boxes as each task lands. Every task ends with a verification step; do not start the next task on a red check.

**Goal:** Ship the release users experience as “a small 1.2.3 patch” but which actually rebuilds the studio’s ergonomics: attachments that live in the transcript, thinking-aware models, a settings system people can understand, real skills, a rewritten `agent.md`, an in-app guide, a motion system, and a measurable memory/smoothness pass — without changing the local-first promise (no account, no telemetry, no new runtime dependency).

**Architecture:** Three layers change together.

1. **Main process (`electron/`)** — a versioned migration runner, a persisted capability registry, prompt-cache accounting, a `message_files` table + paging ops, a skills schema upgrade, an MCP stdio bridge, and a benchmarkable DB write path.
2. **Renderer (`src/`)** — split settings IA, a new Guide route, chat file cards + viewer, thinking/model capability UI, lazy-loaded routes, selector-scoped store subscriptions, and a CSS motion system.
3. **Docs (`docs/`, `README.md`, `CHANGELOG.md`)** — versioned at 1.2.3, refreshed for the features that actually exist, plus a generated handbook mirror.

**Tech Stack:** Electron 33 main process (Node built-ins only), React 18 + zustand 5, sql.js SQLite, Vite 5 (`?raw` markdown imports), existing `scripts/run-all-tests.mjs` harness (headless / e2e-local / e2e-attach / manual).

**Spec:** this document. Source material: source audit on 2026-10-26 (`src/components/*`, `electron/*.ts`), `CHANGELOG.md` §1.2.0–1.2.1, and the carry-over list in `docs/superpowers/plans/2026-10-24-v1.2.5-reliability.md`.

## 1. Global constraints

- **No new runtime dependencies.** Everything uses Node built-ins, existing React/zustand/sql.js/marked/DOMPurify/highlight.js. Dev-only tooling (puppeteer-core, esbuild) is already present.
- **No breaking IPC or DB changes.** Existing ops keep their shape; new data is additive. A 1.2.1 database must open in 1.2.3 and vice versa (1.2.3 only adds tables/columns + `user_version`).
- **Local-first invariants.** No telemetry, no network call at boot. The only outbound traffic remains the user’s provider and (in the 1.2.5 plan) an opt-out update check.
- **Every user-facing string exists in `en` and `id`** (`src/i18n.ts`), including the new Guide chrome and all error states.
- **Every new interaction must be reachable from the command palette**, and every new route from the sidebar.
- **Motion is opt-out:** `prefers-reduced-motion` and the new Motion setting win over every animation. Animate `opacity`/`transform` only.
- **Budgets are enforced by tests, not vibes:** no unbounded in-memory map, no timer/listener without teardown, no log over 300 lines, no cache without a size or byte cap.
- **Tests stay offline.** Headless suites may only talk to localhost mocks and temp SQLite files.

**Known leaks / perf debt to fix (file:line anchors for the implementer):**

- `src/components/Composer.tsx` — `const ui = useUi()` and `const { projects, providers, userPrompts } = useData()` re-render the composer (and its textarea) on any toast/data change.
- `src/components/Sidebar.tsx` — full `useData()` subscription; every streamed token updates `chats.updated_at`-adjacent state.

- `src/App.tsx` — every view is statically imported into the main chunk (Settings alone is ~1,250 lines).
- `electron/db.ts` — `persistNow()` exports the whole DB (`sql.js` copy) on every dirty write; acceptable, but must stay dirty-gated and out of read paths.

## 3. Architecture decisions

| # | Decision | Chosen | Rejected / why |
|---|---|---|---|
| D1 | Migrations | `PRAGMA user_version` + ordered statements + `.bak` before the first change; refuse a newer DB | More `try/catch` ALTERs (unverifiable, no rollback) |
| D2 | Chat file storage | Text rows in `message_files` (≤ 256 KB/file, ≤ 8 files, ≤ 1 MB/message), content loaded lazily by IPC | Blobs on disk (orphan cleanup, backup/sync complexity); base64 in messages (bloats every query) |
| D3 | Transcript loading | `getMessagePage(chatId, before, limit)`; renderer keeps a ≤ 200-message window; `getMessages` stays for export/tests | Full load + client window (memory scales with chat length) |
| D4 | Capability truth | Probe results persisted in `settings.modelCaps` (TTL 14 days, ≤ 120 models) + family inference in the renderer for instant UI; **observed** cache counts override inference | Probing every launch (costly, latency); trusting model names only (wrong for relays) |
| D5 | Thinking gating | `no` → hide controls and never send thinking parameters; `yes` → show with budget; `unknown` → show a muted “unverified” control and a Verify action | Always showing On/Off (current) |
| D6 | Settings IA | Keep every existing section id (deep links, `settings-plugins` route) and add groups + search + `settingsMode: 'simple' \| 'advanced'` | Dropping/retyping ids (breaks routes, tests, automations) |
| D7 | Skills | Builtins seeded idempotently by stable id; **new skills start disabled**; per-chat opt-out stored in `chats.skills_off` | Relying on the global checkbox list only (no per-chat control) |
| D8 | Guide content | Markdown files under `src/guide/{en,id}/*.md` imported with `import.meta.glob(..., { query: '?raw' })`, rendered by the existing markdown pipeline | A docs webview (extra IPC, no offline search); hardcoded JSX (translation pain) |
| D9 | MCP | One child process per enabled server, newline-delimited JSON-RPC 2.0, tools namespaced `mcp__{server}__{tool}`, 30 s timeout, explicit Enable per server | Auto-starting every registered server (surprise process execution) |
| D10 | Motion | CSS custom properties + `data-motion` on `<html>`; transform/opacity only; animation only on the newest streamed bubble | JS animation libraries (bundle + jank); animating list rows (paint storms) |

## 4. Schema and contract changes

### 4.1 SQL (produced by Task 1)

```sql
-- chat files (attachments that belong to a sent message)
CREATE TABLE IF NOT EXISTS message_files (
  id TEXT PRIMARY KEY,
  chat_id TEXT NOT NULL,
  message_id TEXT NOT NULL,
  name TEXT NOT NULL,
  kind TEXT DEFAULT 'file',        -- file | story | chapter
  bytes INTEGER DEFAULT 0,
  content TEXT DEFAULT '',
  created_at INTEGER
);
CREATE INDEX IF NOT EXISTS idx_message_files_message ON message_files(message_id);
CREATE INDEX IF NOT EXISTS idx_message_files_chat ON message_files(chat_id);

-- skills v2
ALTER TABLE skills ADD COLUMN description TEXT DEFAULT '';
ALTER TABLE skills ADD COLUMN builtin INTEGER DEFAULT 0;
ALTER TABLE skills ADD COLUMN source TEXT DEFAULT 'user';   -- builtin | user | imported
ALTER TABLE skills ADD COLUMN updated_at INTEGER;

-- per-chat skill opt-out (JSON array of skill ids)
ALTER TABLE chats ADD COLUMN skills_off TEXT DEFAULT '[]';

-- prompt-cache accounting on assistant turns
ALTER TABLE messages ADD COLUMN tokens_cached INTEGER;
```

`SCHEMA_VERSION = 4` (v1.2.0 baseline was implicitly 3 in the 1.2.5 plan; 1.2.3 is the first release that stamps it).

### 4.2 DB ops (additive)

```ts
// paging + files
getMessagePage { chatId: string; before?: number; limit?: number } -> { messages: Message[]; hasMore: boolean }
addMessage     { …existing, files?: { name: string; kind: 'file'|'story'|'chapter'; content: string; bytes: number }[] }
               -> Message & { files: MessageFileMeta[] }
listMessageFiles { chatId: string } -> MessageFileMeta[]          // no content
readMessageFile  { id: string } -> { name: string; bytes: number; content: string }
// skills
saveSkill  { id; name; description?; content; enabled; source? }   // extended, additive
resetSkill { id }                                                  // builtin → shipped content
// maintenance
dbStats    -> adds chatFiles: number, chatFileBytes: number
compactDb  -> also deletes orphaned message_files
```

`deleteMessage`, `deleteChat`, `deleteProject` and `resetAll` must delete `message_files` rows in the same operation.

### 4.3 Types (renderer, `src/types.ts`)

```ts
export interface MessageFileMeta { id: string; message_id: string; name: string; kind: string; bytes: number }
export interface Message { /* …existing */ files?: MessageFileMeta[]; tokens_cached?: number | null }
export interface ModelCapabilities {
  model: string; tools: boolean; streaming: boolean; thinking: boolean;
  contextTokens: number;
  ok: boolean; error?: string; probedAt: number;
}
export type CacheMode = 'auto' | 'explicit' | 'none' | 'unknown';
export interface ModelCacheProfile { mode: CacheMode; maxTokens: number; minTokens: number; ttlSeconds: number }
export interface SkillRow { /* …existing */ description?: string; builtin?: number; source?: string; updated_at?: number }
```

`settings.modelCaps` row shape: `Record<`${providerId}::${model}`, { caps: ModelCapabilities; cacheObserved?: { cachedTokens: number; at: number } }>`.

## 9. Risks and rollback

| Risk | Mitigation / rollback |
|---|---|
| Chat files bloat the DB | 256 KB/file, 8 files, 1 MB/message, main-process enforcement, Settings → Data size + clear action; the whole table can be dropped without affecting transcripts |
| Migration corrupts a DB | `.bak` before the first change, in-memory snapshot restore, `BEGIN/COMMIT`, refuse newer schema; rollback = restore the `.bak` |
| Prompt cap truncates a user’s attachment | Explicit `[truncated]` marker in the injected block and a visible char count on the card |
| Capability inference is wrong for a relay | `unknown` is always allowed; the probe and the first real reply correct it; thinking falls back to off only after a provider rejection |
| Settings split breaks deep links | Section ids are frozen; a test asserts every route and palette entry resolves |
| Lazy routes flash on slow disks | Suspense fallbacks mirror the view chrome; keep Chat/Sidebar eager |
| MCP child processes leak or hang | Explicit enable, 3 restart attempts, 30 s call timeout, kill on quit, status/log surface, tests that assert process exit |
| Guide markdown grows the bundle | Raw imports of ≤ 18 small files; if total > 250 KB, switch to `import.meta.glob(..., { eager: false })` and split per article |
| Motion causes jank | Only transform/opacity, newest-bubble-only, perf test enforces frame budget |
